# 2026-10-28 灵感与长篇增量修订记录（非执行标准）

本文件只记录实际变动与**留待后续真实运行的验证项**。唯一小说业务标准仍为 `server/shared/src/执行标准.ts` v252；本文件不是第二份标准，不得用于放松质量 Gate 或替代测试。

## 已调整的实际执行路径

- 灵感发现：固定原池生成及筛选仍保留分类、来源事实、因果兑现和同构的独立审查；完整卡仍保留可读性、人物吸引力及质量审查。移除可选备选池生成、主备联合复核和其失败后的额外重审；只在存在可用原池身份、真实缺陷和独立复核预算时针对问题项换选。局部修订和换选的授权条件已分开；无有效改变时不再反复审核相同卡。
- JSON：`llmCallWithRetry` 与 `safeExtractJson` 的历史行解析、截断片段及非贪婪正则补救已清理，只保留统一语法修复、完整均衡结构提取与完整校验，不允许内层片段冒充完整独立质量结论。移除仅 `pool|selection` 两种实际阶段之外的旧混合提示词分支。
- 长篇结构：全书主线及结局承诺、各卷骨架优先建立，首次细纲窗口为约20章；随着已写正文将窗口消耗至触发阈值（约5章）时，再分最多4章的批次生成补纲至前瞻窗口；不预生成全书数百章详细事件。已写正文、原有大纲和创作宪法属于只读来源。
- 长篇稳定性：同项目补纲请求串行，避免流式与普通写作路径并发重复购买模型调用；每批先校验章纲合同及独立来源事实，再用 `BEGIN IMMEDIATE/COMMIT/ROLLBACK` 事务写入，并检查作者正文和现存章纲防止竞态覆盖。
- 权威事实与新实体：滚动提示词继承已确稿世界、卷计划、前章纲、近期正文、已建档人物索引、组织、地点、全部活动伏笔及已确认动态状态；候选实体单独标注 `newEntities`，要求名称和逐字原文证据同章出现。已审核的提案仅写入 `state_items` 待确认项，不自动将其升级为硬事实。作者通过原有 `/projects/:projectId/state/items/:id/confirm` 确认时重新核验原章纲证据，再复用角色、组织、地图及伏笔领域服务建档；服务不可用、来源变化或同名冲突均停止，数据库事务回滚。含未确稿／已拒绝新增实体的章节须先确稿或修订章纲，正文模型调用前阻断。正文两入口均读取已确认组织，避免组织信息只存在于滚动章纲而不进入写作。

- 同一新增实体在不同滚动批次重复出现时，按类型与名称复用既有待确认档案，不再因引用句不同重复建档；后续章节在使用此前未确稿实体前也会被正文前置门禁阻断，而不只检查本章新出现的实体。

- 被作者拒绝的实体只有在有关章纲文本与场景确实不再引用该名称后才解除正文前置阻断；其余待确认实体的跨章引用仍阻断。普通正文入口按数据库真实章序而不是可选请求参数执行此校验。

## 保留的必要独立质量审核

上游来源/分类/流派/因果审核与跨候选同构审核不合并为模型自评；完整卡可读性与呈现审核也继续独立。滚动新章纲仍通过原有事实来源审查，缺省 `newEntities` 不视为通过。不凭空继承未验证的新角色或故事规则。
