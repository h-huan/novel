# AI 小说写作平台用户指南

## 启动

需要 Node.js 22 或更高版本。

从源码运行时，首次在 `server` 和 `desktop` 目录分别执行 `npm ci`。正常使用只需在 `desktop` 目录运行 `node scripts/dev.js`：该命令绕过 Windows 的 `npm.cmd` 命令壳，桌面启动脚本会先编译当前后端，再隐藏启动该编译产物，热更新重启也不经过 CMD。不要同时运行 `server/npm run start:dev`，否则会产生第二个后端、额外命令窗口和端口占用。只有单独调试后端时才运行后端开发命令。

桌面模式把数据库与模型配置放在 Electron 用户数据目录中。

## 先配置模型

进入“设置 → 模型配置”：

1. 选择当前使用的省钱、常规或高品质模式。
2. 为该模式选择“日常模型”。
3. 按需为灵感、大纲/架构、正文、精修/质检分别选择模型。
4. 点击“保存配置”，确认后再点击“启用此模式”。仅切换配置列不会改变当前启用模式。

实际路由规则固定为：指定场景模型优先，未指定时使用当前模式的日常模型。两处都未配置会停止任务并提示，不会改用另一个模型、提供商或模式。

API Key 以提供商保存，例如 DeepSeek Key 对应 `deepseek`；场景中选择具体模型名，例如 `deepseek-v4-flash`。调用时具体模型名保持原样，Key 从对应提供商读取。

切换模式后，系统只读取新模式那一列。若只配置了“省钱”列却切到“常规”，常规模式仍属于未配置。

## 创建作品

新建作品时确认以下字段：

- 长篇、短篇或剧本
- 目标平台
- 目标总字数
- 分类
- 故事基调
- 文风
- 网文流派
- POV
- 目标读者
- 章节目标字数范围

这些内容保存为项目唯一创作宪法。后续世界观、角色、大纲、正文和精修统一继承它。设置对象中不能再保存另一份平台、基调或风格。

篇幅口径只在执行标准一处定义（桌面端 `/module-standards`「执行标准」页面，机器权威为 module-standards seed），短篇/长篇的目标总字数区间以那里为准，页面与文档不另写一套；新建作品页会在填写处直接显示当前区间。章节字数只读取目标平台基准和项目创作宪法。填写目标总字数后严格执行，留空时由题材的事件链和人物弧决定。

## 写作流程

1. 灵感：根据用户输入、长短篇和目标平台一次批量生成题材卡；后端自动读取近期历史作品，比较职业场景、关系结构、压力来源、核心机制、真相载体和反转，淘汰换名复用。每张卡需说明熟悉类型外壳、少见组合及主动避开的历史模式。首批缺项或未通过 Gate 时只用当前灵感场景配置的同一模型补齐一次。
2. 世界观、角色、大纲：每次模型调用记录运行状态、模型、上下文版本和标准快照。
3. 跨阶段 Gate：项目激活前先把世界规则编译为主体、对象、载体、触发条件和能力范围，再生成章节分工。审查若给出可执行 `retain/fix`，系统先零模型编译成章节责任补丁，只复审一次；仍有问题才使用历史效果更好的语义重规划。每轮按实际减少的问题比例学习，下一次把有效策略前移到首稿。
4. 正文：必须关联详细章纲并满足本章目标字数。生成后执行多维质量评审、AI 痕迹指纹和大纲一致性检查。
5. 精修：只修复已定位的问题，复检后比较前后结果。证据不完整、关键维度跌破下限、显著退步或新增严重问题时回滚；不因评审器数分的小幅波动回滚已验证的阻断修复。
6. 学习：修复与评审次数不预设为固定轮数。系统记录策略成功率、问题减少比例、耗时、token 和副作用；已验证的部分进展也参与策略排序，使同类问题从后置多轮修复逐步前移到生成前约束。

章节数由目标总字数、单章 3000–5000 字区间、事件链和人物弧共同决定，没有固定数量。章节节拍也不按“每三章一个爽点”切分；每章需有可感知推进，高光、反转、伏笔和强悬念按章节职责出现，终章负责回收与收束。

## 质量评分

项目、世界观、角色、大纲、章节分别显示多维评分。评分必须附带当前材料中的证据；缺上下文、缺引用或材料不足时显示“未评估/证据不足”，不会补默认高分。

Blocking 问题不能被总分抵消。世界观、角色、大纲、正文或精修产生 Blocking 问题时，内容不会被当作合格结果交付。

## 质量看板

平台首页展示平台范围的真实质量数据；单本项目首页展示该作品数据。可按作品、类型、平台和时间查询。内容包括：

- 当前问题和严重度
- ProjectScore、WorldScore、CharacterScore、OutlineScore、ChapterScore
- 字数达标情况
- 平台、分类、基调、文风、流派、视角六维契合度
- 生成成功、失败、重试和卡点
- 自动修复前后结果
- 问题新增与解决趋势

没有作品或没有合格质检材料时显示空状态或未评估。

## RAG 与向量索引

RAG 用于从本项目已有的角色、世界观、地点、伏笔、摘要和前文中检索相关上下文。它是应用内部能力，不需要用户配置 Embedding API Key。

随应用提供的本地语义模型可用时会更新索引；模型文件缺失时跳过语义索引，创作流程继续使用结构化上下文。页面不会要求额外配置，也不会用远程 Embedding 服务自动替代。

## 数据位置与端口

桌面管理端固定使用 5173，服务端固定使用 3100，两者独立启动。管理端只检查服务端连接，不会创建、关闭或占用服务端端口；端口冲突时不会自动切换端口。

桌面数据保存在 Electron 用户数据目录的 `server-data`。首次切换到该目录时会从当前仓库旧的 `server/data` 迁移一次数据库和模型配置。
