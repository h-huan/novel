# 使用指南

本文件只说明怎么使用项目，不维护第二套执行规则。

## 启动

从仓库根目录分别打开两个终端。后端独立启动：

```powershell
cd server
npm ci
npm run start:dev
```

桌面端独立启动：

```powershell
cd desktop
npm ci
npm run dev
```

桌面端命令启动 Vite 与 Electron 窗口，**不会自动拉起或重启后端**；后端需要在自己的终端单独启动。后端默认地址：`http://127.0.0.1:3100`。

## 主要入口

- `/discover`：灵感发现与创建小说的唯一入口。
- 灵感发现会先固定你的创作要求；跨分类发现时，各候选按自己的分类取得投稿标签候选，补位沿用同一来源；未手动指定标签时，缺少任何必要分类的可核验标签会在发起模型调用前提示，不消耗生成额度；未选择的选项会随各个候选一次确定，后续故事卡继承这些值。候选数量和已过审数量分别显示，标签正确不代表故事已经合格。候选生成前就使用你已选项对应的执行要求和有来源的分类写作说明；公开说明与投稿后台分类、体量及收益证据分别记录。若前置审核已确认缺额，系统可在原预算内提前准备同一次补位，仍逐项完成原审核。完成前置审核的题材接续成卡，缺卡补位沿用同一调度和原预算；完整卡在已预留逐卡终审额度时即时进入同一限流队列，只预留整体审核的短批仍合并终审；审核按原题材身份记录，分组先后不代表质量高低；完整卡全部终审通过且达到请求数量后才显示完成。明确拒绝项的空条件引用由程序按未提供处理，保留拒绝，不为此额外调用纠错。未审、未知、拒绝或停止项不计合格；数量不足显示未完成，已合格卡保留供查看与诊断。本轮实际目标为灵感发现整次请求≤10分钟，仍按本次请求数量交付全部审核合格的完整卡；不通过或未审卡不计入。实际耗时和交付数量以本次运行记录为准，行动与事实审核通过更细原文地址核对同条目中的并列结果；条件从句与实际结果合并核对，保留完整上下文，不把标点分段当质量判定；事实修订须实际改变审核点名的可定位断言，短引文也不能遗漏；未被追责等事件本身不代表社会评价已成立。结构推进问题按正式规则编号选择现有结构修复策略，仍受原预算与独立复查约束。具体质量与修复要求见唯一执行标准。
- `/projects`：项目列表。若项目仍在创建或仍有模型调用运行，请在进度页查看，不要同时启动断点恢复；失败恢复只在先前任务结束后清理下游生成资料，原已确认作品不会因重建失败而被误降为失败状态。
- `/project/:id/dashboard`：项目工作台。
- `/project/:id/outline`：小说架构与章节规划。
- `/project/:id/writing`：正文写作。
- `/project/:id/writing-quality`：质量与一致性检查。
- `/module-standards`：查看当前执行标准的代码镜像。

## 模型配置

在设置页配置灵感、架构、正文、润色/质检和日常场景的模型。未配置对应模型时，系统应明确停止并提示，不静默降级到其它模型。

## 执行标准

小说业务与质量规则的唯一来源是 `server/shared/src/执行标准.ts`；`QUALITY_EXECUTION.md` 仅保留旧链接兼容，不维护独立规则。本指南不重复篇幅、平台阈值、质量 Gate、AI 痕迹或修复规则。

## 长篇新增人物、地点、势力与伏笔

写作推进至原有细纲窗口末端时，长篇自动滚动生成下一批章纲；也可进入「大纲 → 全书骨架 · 章节列表」，选择「补 1 章／补 3 章／补 5 章／补 10 章」手动追加。手动补纲不需要先点选任何章节，不会重跑全书规划、改动已存章纲或覆盖正文；仍执行卷级范围、前文接力、事实与行动的独立一致性审核。若卷级剩余章数不足或原章节顺序存在缺口，系统会在发起模型调用前拒绝，请先检查原有结构。短篇在创建时已经完成全篇章纲，不使用长篇滚动补纲。新有名实体会与章节原文证据一起进入状态确稿中心，先是待确认资料，不会直接更改既有人物、组织、地点或伏笔的确稿档案。请在状态确稿中心逐项审查并确认；已有事实如被新提案冲突，先更改章纲而非覆盖已确认资料。拒绝提案后也须先修改相应章纲。涉及未完成确稿的章节会在正文调用前停止，不浪费正文模型费用。

## 本地验收

在应用已经运行并完成真实生成后，从仓库根目录执行：

```powershell
node verify-local.mjs --project <项目ID>
```

需要同时执行仓库测试：

```powershell
node verify-local.mjs --project <项目ID> --full
```

需要再执行 E2E：

```powershell
node verify-local.mjs --project <项目ID> --full --e2e
```

每次验收覆盖生成：

- `verification/latest.json`
- `verification/latest.md`

`verification/` 已加入 `.gitignore`，只保存当前本机最新验收状态；历史由 Git、CI 与数据库运行记录承担。
